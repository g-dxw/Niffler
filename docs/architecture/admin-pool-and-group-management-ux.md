# 管理端号池账号与分组占用处理

## 目标

- 号池管理主列表支持批量启用和批量停用账号，管理员可以一次恢复筛选出来的禁用账号。
- 用户分组删除失败时，管理员能看清仍在使用该分组的 API Key，并能按 API Key 绑定分组筛选用户做人工审查。
- 用户分组被 API Key 占用时，管理员可以直接选择另一个分组，把占用 Key 迁移过去后再删除原分组。
- 账号禁用状态说明清楚：禁用来自管理写操作或导入数据，不是调度运行时自动判定的临时状态。

## 非目标

- 不改变号池调度算法和账号状态计算规则。
- 不新增账号禁用审计字段；历史禁用原因仍不能从现有数据反推出。
- 不自动选择替换分组；目标分组必须由管理员明确选择。
- 不绕过只读分组、默认分组和 Niffler Core 迁移冻结规则。

## 行为变化

- 号池账号选中栏新增“启用已选”和“停用已选”，支持当前页选择和“全部筛选结果”选择。
- 批量启用或停用复用现有号池批量操作接口，只修改账号 `is_active`。
- 禁用状态悬浮说明展示禁用含义和可能来源，避免误解为系统自动熔断。
- 用户列表新增“Key 分组”筛选，筛选条件是用户 API Key 的 `group_id`，不是用户本人的成员分组。
- 用户分组删除遇到 API Key 占用时，弹窗展示占用数量和部分 Key 示例，并提供“查看绑定 Key”入口。
- 删除被 API Key 占用的用户分组时，弹窗提供“替换到”下拉框。管理员选择目标分组后，后端在同一个事务里完成：
  1. 校验原分组和目标分组存在，且不是同一个分组。
  2. 将所有绑定原分组的 API Key 改到目标分组。
  3. 删除原用户分组及成员关系。
  4. 返回实际迁移的 API Key 数量。
- 如果管理员不想直接迁移，仍可跳到用户管理按 Key 分组筛选后人工审查。

## 影响范围

- 管理端号池管理页。
- 管理端用户管理页和用户分组弹窗。
- 管理端用户列表接口，新增可选查询参数 `api_key_group_id`。
- 数据层用户分页查询，新增按 API Key 分组过滤。
- 管理端用户分组接口，新增“迁移占用 Key 并删除分组”的原子操作。
- 数据层用户分组删除，新增事务内迁移 API Key 分组并删除旧分组的方法。

## 验证方式

- 前端类型检查通过。
- 后端相关 crate 编译或测试通过。
- 人工验证号池筛选禁用账号后可选择全部筛选结果并批量启用。
- 人工验证删除被 API Key 使用的分组时，能跳到用户管理并按 Key 分组筛出相关用户。
- 人工验证删除被 API Key 使用的分组时，可选择目标分组，完成迁移后旧分组消失，相关 API Key 出现在目标分组下。

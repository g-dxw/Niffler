# Codex 模型目录客户端版本管理

## 目标

- 自动跟随官方 `@openai/codex` 的最新稳定版本，避免旧 `client_version` 导致上游隐藏新模型。
- 新版本必须使用同一真实 Codex 账号与当前版本对比验证后才能生效。
- 官方版本查询或上游验证失败时继续使用上一次成功版本，不影响现有模型权限。
- 保留运维人员固定版本和紧急回退的能力。

## 非目标

- 不自动使用 `alpha`、`beta` 等预发布版本。
- 不根据模型名称猜测或注入上游未返回的模型。
- 不为不同 Codex 提供商分别维护客户端版本。
- 不改变普通 OpenAI、Claude、Gemini 等提供商的模型获取行为。

## 行为变化

- Codex 模型目录请求不再固定使用 `0.128.0-alpha.1`。
- 未设置 `CODEX_MODEL_FETCH_CLIENT_VERSION` 时，后台模型同步任务定期读取官方 npm 包 `@openai/codex` 的 `latest` 稳定版本。
- 发现新版本后，系统使用一个有效 Codex 账号分别请求当前版本和新版本的模型目录。新版本目录非空且不缺少当前版本返回的模型时，才保存为所有 Codex 提供商共用的有效版本。
- 验证账号不要求开启模型自动同步，避免系统启动后新增账号仍无法参与验证。
- 已验证版本和最近检查时间保存在数据库系统配置中，服务重启后继续使用；进程内同时保留最后成功版本，数据库临时不可用时不回退到旧的内置版本。
- 官方版本查询、账号验证或持久化读取失败时，继续使用上一次成功版本；没有历史版本时使用内置默认版本。
- 官方查询或账号验证失败后每 15 分钟重新检查，不进入完整的一天冷却；验证成功或确认没有新版本后一天检查一次。
- 数据库中的版本状态缺失或无法解析时，记录明确告警并使用进程内最后成功版本；没有历史版本时使用内置的已验证版本。损坏记录不得阻止后续检查，下一次成功检查会覆盖该记录。
- 设置 `CODEX_MODEL_FETCH_CLIENT_VERSION` 后固定使用该版本并停止自动发现，适用于临时回退。
- 提供商端点 URL 已显式包含 `client_version` 时，仍以端点参数为最高优先级。
- 模型同步失败时不得清空账号已有的 `allowed_models`。上游虽然返回成功状态但模型目录为空，也按失败处理，不覆盖已有模型权限和上游模型缓存。

## 影响范围

- `codex` 类型提供商的模型目录请求。
- 后台模型自动同步任务和手动刷新模型操作。
- 数据库系统配置新增 Codex 客户端版本及检查时间记录。
- 不影响正常推理请求、计费、模型名称映射和非 Codex 提供商。

## 验证方式

- 单元测试覆盖默认版本、环境变量固定版本、端点参数覆盖和非法版本回退。
- 单元测试覆盖候选目录不减少模型、验证失败后保留旧版本、进程内最后成功版本回退，以及成功和失败检查间隔。
- 单元测试覆盖空模型目录保留账号已有权限，以及损坏版本状态不会阻止后续版本检查。
- 使用 Plus 账号验证最新稳定版本返回 `gpt-5.6-sol`、`gpt-5.6-terra` 和 `gpt-5.6-luna`。
- 自动同步后检查上游原始缓存和账号 `allowed_models`，确认无需手动锁定即可保留 5.6 系列。
- 回归验证 Pro 账号、`gpt-5.5` 和图片生成相关模型不受影响。

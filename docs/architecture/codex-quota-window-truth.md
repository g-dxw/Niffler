# Codex 配额窗口真实来源

## 目标

让 Codex 账号配额展示与最近一次上游响应一致，覆盖 5H、7D、1M 以及上游以后增加的其它窗口。

## 非目标

- 不在 Niffler 本地推算上游没有返回的月额度。
- 不从旧快照补回当前上游已经省略的窗口。
- 不把 `primary_window` 或 `secondary_window` 当成固定业务名称。

## 数据规则

上游窗口的事实字段是窗口时长、已用比例、重置时间和是否达到限制。Niffler 将窗口保存为通用 `windows[]` 项：

- `code`：稳定的内部标识。标准时长使用 `5h`、`weekly`、`1m`；其它时长使用基于秒数的稳定标识。
- `label`：根据真实窗口时长生成的可读名称。标准窗口显示 `5H`、`7D`、`1M`；其它时长按天、小时和分钟显示，不向用户展示秒数代码。
- `window_seconds`：上游返回的精确窗口时长，本地周期用量统计必须优先使用该字段。
- `window_minutes`：上游返回的窗口分钟数，缺失时只在能够从秒数无损换算时生成。
- `used_ratio`、`remaining_ratio`、`reset_at`、`reset_seconds`：直接来自上游或由等价字段计算。

同一账号的普通 Codex 窗口和 Spark 等独立功能窗口必须使用不同的标识，避免把两个功能的额度合并。
持久化快照中的窗口数值必须先验证为 PostgreSQL `BIGINT` 可表示的非负整数；分钟换算为秒时还必须检查乘法范围。异常值只跳过该窗口的本地周期统计，不能使整批用量增量处理失败。

## 兼容规则

7 天窗口继续使用已有的 `weekly` 内部标识，界面统一显示 `7D`。不新增 `7d` 标识，避免同一个窗口产生两套代码，也避免升级后当前周期的本地用量消失。读取已经产生的 `7d` 快照时仍按 7 天窗口兼容处理。

## 验证方式

测试至少覆盖 5H、7D、1M、只有一个窗口、窗口从上游响应中消失、未知窗口时长和旧 `weekly` 汇总兼容；还要确认额度耗尽判断遍历当前所有窗口。

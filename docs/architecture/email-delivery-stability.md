# 邮件发送稳定性改造

## 目标

让注册验证码邮件稳定可用，发送失败对管理员可见，注册接口不再被 SMTP 发送耗时拖慢。

## 非目标

本次不接 Cloud Mail，不新增短信验证，不改变用户账号结构，不改变邮箱唯一性规则。

## 行为变化

发送验证码接口成功返回表示验证码已生成且邮件任务已创建；邮件是否发送成功在后台发送记录查看。

后台发送任务一旦被 worker 接手，必须从“等待中”推进到“正在发送”或最终状态。SMTP 配置缺失、发件人缺失、任务内容无效这类确定错误直接记录为失败，不能继续停留在等待队列里反复重试。

注册邮箱验证开关和 SMTP 测试必须使用同一套“配置完整”标准：SMTP 服务器、用户名、密码、发件人邮箱都已填写才算完整。配置不完整时，注册设置接口返回 `email_configured = false`，前端不能开启注册邮箱验证。

验证码邮件进入队列后，如果对应邮件任务最终失败，验证码状态接口必须返回失败状态和失败原因，并允许用户立即重新发送验证码；不能继续用这条已经失败的验证码记录阻止用户重发。

邮件发送 worker 的任务锁必须覆盖一次 SMTP 发送的最坏超时窗口，避免多 background 实例在慢 SMTP 下重复发送同一封邮件。

## 影响范围

影响注册验证码发送、后台 SMTP 测试、邮件配置页和后台任务记录。

## 验证方式

运行注册验证码相关 Rust 测试、后台系统接口路由测试、前端类型检查，并在本地后台完成一次 SMTP 配置保存和测试发送流程。

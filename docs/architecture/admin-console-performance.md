# 管理控制台首屏性能修复

## 目标

- 降低生产环境打开管理控制台时的首屏等待和卡顿。
- 避免首屏自动触发容易超时的外部版本检查。
- 避免 Codex 号池账号列表在常规展示场景实时扫描大表。

## 非目标

- 不改变请求计费、用量结算和号池调度规则。
- 不改变版本检查接口本身的返回结构。
- 不新增后台定时任务或迁移历史数据。

## 行为变化

- Dashboard 每日统计继续传 `tz_offset_minutes`，优先保证“本月费用”和每日统计表使用同一时区边界。
- 每日统计的性能优化不能依赖丢弃时区参数；当用户时区不是 UTC 时，后端可以按明细表统计以保证金额口径正确。
- 管理员布局挂载时不再自动请求 `/api/admin/system/check-update`；管理员点击版本按钮刷新时才请求。
- Codex 号池账号列表默认只展示账号状态快照里的 5H/周窗口用量，不再实时聚合 `usage` 和 `usage_settlement_snapshots`。

## 影响范围

- 管理端和用户端 Dashboard 的每日趋势统计路径。
- 管理控制台顶部/侧边栏版本按钮的自动刷新行为。
- 管理端 Codex 号池账号列表的窗口用量展示。

## 验证方式

- 前端单元测试确认 Dashboard 日报请求携带本地时区偏移。
- 前端单元测试确认 MainLayout 挂载后不自动调用版本检查接口。
- 后端单元测试确认 Codex 号池列表默认不使用 usage reader 覆盖窗口用量。

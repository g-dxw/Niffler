# 本地执行上游错误透传

## 目标

当本地执行链路已经请求到上游，且上游明确返回“用户请求本身不合法”的 4xx 错误时，Niffler 应直接把该错误返回给用户，不应继续更换账号或服务后包装成平台 503。

## 非目标

- 不把所有 4xx 都改成直接返回；认证失效、额度不足、限流、上游临时异常仍按现有账号状态和重试规则处理。
- 不在最终 503 响应里拼接上游错误；错误是否可返回必须由调度失败分类决定。
- 不改变管理员配置的错误文案替换规则。

## 行为变化

- 图片尺寸超过上游限制，例如 `image dimensions exceed max allowed size` 或 `max allowed size for many-image requests`，视为用户请求错误。
- 这类错误会停止本地换账号和换服务，按上游状态码和错误内容返回给用户。
- 如果错误本身仍适合继续尝试其它服务，例如上游 502/503，Niffler 仍会先继续尝试其它可用服务；当所有服务都失败且最后一次尝试有上游响应 body 时，最终返回给用户和管理详情都使用最后一次真实上游错误。
- 请求记录仍保留实际上游状态码、错误内容和调度决策，便于管理员排查。

## 影响范围

- 影响本地执行链路的同步和流式请求。
- 不影响没有进入上游的入口拦截错误。
- 不影响普通 429、5xx、账号失效、上游认证失败等现有换服务和账号状态处理。

## 验证方式

- 单元测试覆盖图片尺寸错误不再进入“换下一个服务”分支。
- 同步和流式本地执行的失败分类都必须返回停止换服务。

# 生图工作台前端设计

## 范围与入口

生图工作台是 Vue 纯前端功能，普通用户通过 `/dashboard/image-studio` 进入，管理员通过 `/admin/image-studio` 进入。页面复用 Niffler 的用户 API Key、模型目录和 OpenAI 兼容图片接口，不在浏览器中增加独立代理服务。

## 请求与权限边界

1. 页面先加载当前用户可用的 API Key。
2. 页面通过用户模型目录识别具有 `image_generation` 能力的模型。模型名称仅作为旧数据的模型族兜底，并使用前缀/分隔符匹配，避免把图片理解、嵌入或 `imagenet` 等非生图模型纳入。
3. 当前网关 `/v1/models` 使用聊天能力鉴权，不能准确代表 `/v1/images/*` 权限，因此纯前端不使用它过滤图片模型。提交前只确认模型仍在用户生图目录中；Key 对图片接口和具体模型的最终权限由真实图片请求校验，401/403 会显示明确权限提示。
4. 创建任务时，将 `apiKeyId` 写入任务记录，并把完整 Key 和 API 地址作为仅内存凭据快照绑定到任务。排队期间切换页面 Key 不会改变旧任务凭据；完整 Key 不写入 LocalStorage 或 IndexedDB。
5. 文生图调用 `/v1/images/generations`，参考图编辑调用 `/v1/images/edits`。

## 调度与取消

任务状态为 `pending / running / success / error / cancelled`。调度器按创建顺序取任务，最多并发 8 个；任一任务结束后释放槽位并继续队列。运行任务使用独立 `AbortController`，取消排队任务不会发起请求，取消运行任务会终止对应请求。重试沿用任务创建时的 `apiKeyId`，必要时重新从服务端读取该 Key。

## 浏览器存储

- 页面内存和 LocalStorage 均按用户保留最近 300 条任务；淘汰时会终止任务并释放 Blob URL、参考图和任务凭据，不保存完整 Key、Base64 或 Blob URL。
- IndexedDB 按 `userId + taskId` 保存图片 Blob。
- 每次任务记录变化及页面加载时，缓存清理器会删除不在最近 300 条记录中的孤立图片。
- 整个生图图片缓存上限为 250 MiB；超限时跨用户按 `cachedAt` 从旧到新淘汰，原图不缩放、不裁剪、不重编码。清理扫描通过游标只保留元数据，不在内存中聚合全部 Blob。
- 删除单任务或清空全部任务时，同步删除对应缓存；界面操作均有二次确认。

## 测试与验收

专项测试覆盖请求格式、SSE 完成语义、尺寸与比例、提示词和高级参数、任务耗时、用户存储隔离，以及排队、并发、切换 Key、提交快照、取消、任务记录上限、重试记录保留、跨用户缓存容量和孤立缓存淘汰。模型筛选包含 `image_generation` 正向用例，以及显式禁用、`image_input`、图片理解、图片嵌入和通用图片分类模型的反向用例。管理员菜单需同时验证可见入口。

# 模型目录界面口径

## 目标

让管理员能区分两个不同动作：用户请求模型名如何归到平台统一模型，以及平台发给上游时使用哪个真实模型名。同时让管理端的提供商数量可以直接看到明细。

## 非目标

不向普通用户暴露具体提供商名称、上游账号、Key 或端点信息。用户侧只展示可用模型、价格、能力和调用方式。

## 行为变化

- 全局模型详情中的“模型映射”改为“别名匹配”。它只表示用户请求的模型名是否归到当前全局模型。
- 新增别名规则时默认按精确别名处理，保存前转成安全的完整匹配规则；正则只作为高级模式。
- 如果精确别名已经是另一个启用中的全局模型名称，保存时拦截并提示管理员先停用或删除同名模型。
- 提供商模型配置中的映射语义保持不变，它表示当前全局模型请求上游时使用的真实模型名。
- 管理端模型列表里的提供商数量应作为入口，点击后直接进入模型详情的提供商链路明细。
- 管理端模型详情的提供商统计卡片也应能切换到提供商链路明细。

## 影响范围

只影响管理端模型管理界面的文案和入口。调度、计费、权限和用户侧公开模型接口不变。

## 验证方式

- 打开管理端模型管理页，点击提供商数量，详情抽屉应直接展示提供商链路。
- 打开全局模型详情，原“模型映射”页签应显示为“别名匹配”。
- 保存别名规则后，仍写入 `config.model_mappings`，原调度行为不变。
- 使用精确别名 `claude-opus-4.8-thinking` 时，不能误匹配 `claude-opus-4x8-thinking`。

# 仪表盘用量统计时区一致性

## 目标

用户仪表盘同一页面内的“本月费用”和每日统计表必须使用同一套时区边界，避免用户看到本月合计小于本月内每日费用合计。

## 非目标

- 不改变费用计算字段，用户侧仍展示 `total_cost_usd`，不展示平台上游真实成本 `actual_total_cost_usd`。
- 不重建历史预聚合数据。
- 不调整默认统计周期，上方汇总仍默认本月，下方趋势仍默认最近 7 天。

## 行为变化

- `/api/dashboard/stats` 和 `/api/dashboard/daily-stats` 都应接收同一个 `tz_offset_minutes`。
- 每日统计按用户本地日期切分，不再为了使用 UTC 日预聚合而丢弃时区。
- 当传入非 UTC 时区时，后端会按明细表统计每日数据，保证日期边界与上方汇总一致。

## 影响范围

- 影响用户仪表盘趋势图、每日统计表、模型费用拆分图。
- 不影响请求计费本身，不影响钱包扣费，不影响用量明细记录。

## 验证方式

- 前端测试应断言每日统计请求携带 `tz_offset_minutes`。
- 手动验证同一用户在同一时区下，本月内每日费用合计不会超过本月费用。

# 用户使用记录后端分页

## 目标

普通用户“使用记录”列表按后端分页、后端筛选返回，分页总数使用服务端统计的真实总数，不再只统计当前页面已经拿到的记录。

## 非目标

- 不改变管理员使用记录接口。
- 不改变计费、钱包扣款、套餐扣除和使用记录写入流程。
- 不新增历史数据迁移。

## 行为变化

- `/api/users/me/usage` 支持 `model`、`provider`、`api_format`、`status`、`client_family` 筛选。
- `/api/users/me/usage` 返回的 `pagination.total` 表示当前时间范围和筛选条件下的真实记录总数，不是当前页长度。
- 前端用户使用记录页翻页、调整每页数量、搜索、切换模型/API 格式/状态/客户端时都会重新请求后端。
- 用户页统计请求会传 `include_records=false`，只取统计汇总，不再额外读取一页记录。

## 影响范围

- 影响普通用户使用记录列表和分页显示。
- 管理员使用记录仍使用原有管理端分页接口。
- 已有使用记录数据不变。

## 验证方式

- 前端单测覆盖用户记录分页参数、筛选参数和 `pagination.total`。
- 后端测试覆盖 `/api/users/me/usage?limit=2&offset=0` 返回 2 条记录，同时 `pagination.total` 仍返回真实总数。

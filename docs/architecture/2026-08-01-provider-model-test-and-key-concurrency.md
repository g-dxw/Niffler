# 提供商测试与账号并发显示

## 目标

- 在提供商详情的账号列表显示每个账号当前正在处理的请求数，并与账号并发上限同时展示。
- 支持从单个账号发起请求测试，测试请求只能使用指定账号，不触发账号池切换。
- 让提供商测试和单账号测试共用同一套协议选择、结构化参数、请求追踪、错误详情和图片预览。
- 默认按协议模板生成请求，不要求管理员先编辑 JSON；保留请求头和请求体 JSON 作为高级排错入口。
- 覆盖现有可测试协议，并对 OpenAI 图片端点和 Responses 图片工具保留图片参数与预览能力。

## 非目标

- 不重写现有提供商模型测试适配器、请求转换和响应解析链路。
- 不把账号并发数写入数据库；实时值继续从 Redis 运行时请求令牌读取。
- 不改变正常业务请求的账号调度、失败切换、限流或并发上限判定。
- 不在本次改动中新增尚未被现有适配器支持的上游协议。

## 行为变化

1. 账号列表接口在每个账号对象中增加 `current_concurrency`，值为当前 Redis 请求令牌中属于该账号的令牌数量。
2. 测试请求支持 `api_key_id`。有该字段时，后端验证账号和端点匹配后只构造一个测试账号，不经过账号池排序或故障切换。
3. 模型测试弹窗默认显示端点协议、模型映射、测试提示词和适用的图片参数；支持流式响应的协议显示流式开关，嵌入和重排等同步协议不显示。流式开关会影响普通上游请求，账号或端点明确要求固定流式方式时仍以该强制规则为准。请求头/请求体 JSON 收纳到高级编辑区域。
4. 账号列表增加“测试账号”入口，调用与提供商测试相同的测试弹窗和结果展示。
5. 账号详情打开期间定时刷新账号列表，测试时可以看到当前并发数的变化。

## 影响范围

- Rust 网关：Redis 请求令牌按账号聚合、账号列表响应、模型测试账号筛选。
- Vue 前端：账号类型、账号列表、模型测试弹窗、模型测试 composable 和模型列表测试入口。
- 运行时兼容：Redis 不可读时当前并发回退为 `0`，不影响请求执行；测试账号不存在或不支持端点时返回明确错误。

## 验证方式

- Rust 单元测试验证请求令牌按账号聚合、账号筛选只生成一个账号、普通账号列表字段和标准测试的流式选择。
- 前端组件测试验证结构化协议表单、图片参数、高级 JSON 开关和单账号测试参数。
- 运行网关相关 `cargo test`、前端类型检查和模型测试/提供商详情相关 Vitest。

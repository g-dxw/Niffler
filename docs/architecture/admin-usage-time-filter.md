# 管理端使用记录时间筛选

## 目标

让管理端“使用记录/请求记录”支持按具体时间段查询，不只支持按日期查询。

## 非目标

- 不新增数据库表或索引。
- 不改变请求记录的写入流程。
- 不改变默认时间范围和已有 `preset/start_date/end_date` 参数语义。

## 行为变化

- 现有 `preset/start_date/end_date` 继续可用，日期范围仍按用户时区转换成本地整天。
- 自定义时间段新增 `start_time/end_time` 参数，格式为 `YYYY-MM-DDTHH:mm` 或 `YYYY-MM-DDTHH:mm:ss`。
- 当请求里包含 `start_time/end_time` 时，后端优先使用具体时间，不再只按整天查询。
- 时间段采用半开区间：`start_time <= created_at < end_time`，避免相邻时间段重复统计边界请求。
- 前端使用记录表的自定义时间选择器改为日期时间选择，其他页面默认仍使用日期选择。

## 影响范围

- 管理端和用户端使用记录 API 的时间范围解析。
- 管理端使用记录表的时间筛选控件。
- 统计、聚合和活跃请求接口会复用同一个时间范围解析，因此传入具体时间时也按具体时间统计。

## 验证方式

- 后端测试覆盖同一天内按小时筛选请求记录。
- 前端测试覆盖时间选择器在开启具体时间模式时发出 `start_time/end_time`。
- 运行相关后端和前端测试，并执行格式检查。

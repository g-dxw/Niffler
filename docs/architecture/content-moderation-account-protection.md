# 可配置上游前置内容审查

## 目标

在请求进入受保护 Provider、Niffler Core 上游服务或上游账号前，先对用户输入做内容审查，降低上游账号因违规内容被限制或停用的风险。审查命中时由本地返回 403，不再请求被保护上游。

## 非目标

本次不自动封禁用户，不替代上游或平台的后置审查，不审查系统提示词、模型回复和工具结果。v1 不改变原模型用量结算规则；审查通过时审查成本写入原请求 Usage metadata，命中违规时写入一条失败的 Usage 记录。

## 行为变化

- 默认关闭内容审查。
- 管理员可配置总开关、生效对象、审查级别、模型、多个审查 API Key、Base URL、超时、计费价格和证据保留天数。
- 管理端接口接收 `api_keys` 数组；后端保存为 `api_keys_encrypted`，返回给管理端时只展示 `api_key_count` 和 `api_key_masks`，不回显原文。本功能尚未上线，不保留旧 `api_key` 单字段兼容。
- 保存配置时 `api_keys` 为空表示保留已保存 Key；只有显式提交 `api_keys_clear: true` 才清空已保存 Key。
- 多个审查 API Key 会按请求轮询使用；某个 Key 请求失败时，本次审查继续尝试下一个 Key，单次审查最多尝试 3 个 Key，全部失败才按“审查失败放行”处理。
- 审查级别支持关闭、只审最新用户输入、审本次请求所有用户输入、审完整请求。
- 审查通过时继续原执行链路，并把审查 Usage 成本附加到原请求记录。
- 审查命中时返回 403，不请求上游，并写入一条审查 Usage 成本记录。
- 审查接口超时、报错或不可用时放行请求，不记录审查扣费，只记录失败日志。
- 同一请求的多候选重试只审查一次，不重复扣费。
- 审查成功时写入独立证据记录，保存用户 ID、API Key ID、Provider ID、上游服务 ID、上游账号 ID、审查模型、分类、分数、哈希和原文。
- 原文只在证据保留期内保存，默认 30 天；过期清理只删除原文，保留分类、分数、哈希和基础审计信息。
- 管理员或审计管理员可按证据 ID 查看原文；每次查看必须写管理审计日志。
- Usage metadata 只保留审查摘要和证据 ID，不保存原文。

## 影响范围

影响 AI 请求候选执行前置检查、Usage 成本记录、审查证据存储、证据过期清理、管理端内容审查配置与证据查看。未开启配置或请求不命中保护范围时，请求路径和原计费行为保持不变。

## 验证方式

- 覆盖默认关闭时不审查。
- 覆盖 Provider、Endpoint、Key 命中范围时才审查。
- 覆盖审查通过继续执行并记录审查成本。
- 覆盖审查命中返回 403、不请求上游并记录审查成本。
- 覆盖审查接口失败时放行且不记录审查扣费。
- 覆盖审查文本提取级别。
- 覆盖命中审查后写入原文证据，证据 ID 可从 Usage metadata 关联。
- 覆盖证据过期清理只清除原文，不删除分类、分数、哈希等摘要。
- 覆盖查看原文需要管理员或审计管理员权限，并写入管理审计日志。
